# ADR-0017 — v0.1 is the Admin API wedge, then a thin slice

**Status:** Accepted
**Date:** 2026-09-22
**Evidence:** `2026-09-20-claude-code-telemetry-surfaces.md` (Analytics API capabilities and limits).

## Context

The Claude Code Analytics Admin API (`/v1/organizations/usage_report/claude_code`) returns daily
per-user aggregates — sessions, lines added and removed, commits, PRs, per-tool accept/reject counts,
per-model tokens and cost — with **nothing deployed to any machine**. It needs only an admin key.

That is a genuinely different adoption path from the managed-settings deployment, and it requires no
approval from anyone.

## Decision

**Phase 1 — the wedge.** A `cardo` Go binary that polls the Analytics API, pseudonymizes
`actor.email_address` at ingest under the same contract as the collector path, writes to ClickHouse
or DuckDB, and drives one Grafana dashboard. Success criterion: runs against an organization's admin
key in under ten minutes with nothing deployed.

**Phase 2 — the thin slice.** Managed settings bundle, collector config, the 13-event hook pack, the
SQL layers, and one dashboard answering: *is our skill / CLAUDE.md being used, by what share of the
fleet, on which content hash* — including stale-version detection.

**The per-engineer self-view is held for v0.2.**

## Consequences

- There is something demonstrable before asking any organization for managed-settings access, which
  is the hardest ask in the whole rollout.
- The analysis layer gets validated against real data before the collection layer is built.
- The self-view is the trust centerpiece and it is deliberately *not* in v0.1. The README states the
  intent. A promise kept in v0.2 is worth more than a half-built authenticated UI in v0.1.
- The Analytics API is daily-granularity and email-identified; it can never answer session-level
  questions. It is a wedge, not a product.

## Rejected alternatives and why

- **Thin slice only**, skipping the wedge. Goes straight to one deployed question answered end to end,
  and requires a deployment conversation before there is anything to show.
- **Thin slice plus friction index plus self-view.** More complete first impression; builds a whole
  authenticated UI surface before the underlying data is proven useful.
- **Full efficiency product before first deployment.** Longest time to real feedback, on a design whose
  central metric is explicitly unvalidated.
